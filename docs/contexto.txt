========================================
2. PROBLEMÁTICA
========================================

La cafetería Sachas enfrenta los siguientes problemas en su gestión diaria:

a) Gestión manual de pedidos: Los pedidos se toman en papel. Se pierden, se
   olvidan, no hay trazabilidad del estado actual (cola, espera, preparación,
   listo). No se sabe qué pedido va primero ni cuánto tiempo lleva.

b) Catálogo desorganizado: No existe una forma eficiente de buscar productos
   por nombre o filtrar por categoría. Agregar, modificar o eliminar productos
   implica tediosos procesos manuales.

c) Fidelización nula: No hay registro formal de clientes ni sistema de puntos
   que incentive la recurrencia. No se sabe quiénes son los clientes más fieles.

d) Sin recomendaciones: No se aprovecha el histórico de ventas para sugerir
   combos o productos relacionados ("los que compraron X también compraron Y").

e) Control de caja deficiente: Las ventas del día se registran en libreta.
   No hay resumen automático de total del día ni historial de transacciones.
   No se sabe cuánto se vendió ni cuántas ventas se realizaron.

f) Procesos sin automatizar: No hay cola de espera, ni temporizadores de
   preparación, ni posibilidad de deshacer acciones errores.

3. SOLUCIÓN — SISTEMA IMPLEMENTADO

El sistema Sachas Café resuelve la problemática con 4 módulos principales,

- Visualización gráfica del Árbol AVL ordenado alfabéticamente por nombre
- Muestra los 3 recorridos: Inorden (ascendente), Preorden, Postorden

--- MÓDULO 2: PEDIDOS (Cola FIFO + Pila + Lista Doblemente Enlazada) ---
Vista: view/pedidos_view.py
Controlador: controller/pedido_controller.py

Funcionalidades:
- Creación de pedidos seleccionando cliente + productos + cantidades

- Recorridos BFS (Anchura) y DFS (Profundidad)

5. DESCRIPCIÓN DE CADA TAD
========================================

--- TAD Cola (Queue - FIFO) - structures/tad_cola.py ---

Implementación de una cola simple con nodos enlazados.
Operaciones: enqueue (encolar), dequeue (desencolar), peek (ver frente),
esta_vacia, tamano, recorrer, vaciar.

Uso en el sistema: La cola_pedidos almacena pedidos recién creados en orden
de llegada. El primero en llegar es el primero en pasar a espera (FIFO).

Fragmento clave:
  def enqueue(self, dato):
    nodo = NodoCola(dato)
    if self.esta_vacia():
      self._frente = nodo
      self._final = nodo
    else:
      self._final.siguiente = nodo
      self._final = nodo
    self._tamano += 1

  def dequeue(self):
    if self.esta_vacia():
      return None
    dato = self._frente.dato
    self._frente = self._frente.siguiente
    if not self._frente:
      self._final = None
    self._tamano -= 1
    return dato


--- TAD Pila (Stack - LIFO) - structures/tad_pila.py ---

Implementación de una pila con nodos enlazados.
Operaciones: push (apilar), pop (desapilar), peek, esta_vacia, tamano.

Uso en el sistema: Cada acción sobre pedidos (crear, pasar a espera, pasar
a preparación, marcar listo) se apila en pila_deshacer. El botón "Deshacer"
hace pop y revierte la última acción.

Fragmento clave:
  def push(self, dato):
    nodo = NodoPila(dato)
    nodo.siguiente = self._cima
    self._cima = nodo
    self._tamano += 1

  def pop(self):
    if self.esta_vacia():
      return None
    dato = self._cima.dato
    self._cima = self._cima.siguiente
    self._tamano -= 1
    return dato


--- TAD Lista Doblemente Enlazada - structures/tad_lista_doble.py ---

Cada nodo tiene puntero al siguiente y al anterior, permitiendo
recorrido bidireccional.

Uso en el sistema: lista_pendientes mantiene los pedidos en preparación,
permitiendo insertar al final y eliminar elementos específicos (porque
cualquier pedido puede marcar como listo o devolver a espera).

Operaciones: insertar_inicio, insertar_final, eliminar, eliminar_primero,
eliminar_ultimo, buscar, recorrer_adelante, recorrer_atras.


--- TAD Árbol AVL (Auto-balanceado) - structures/tad_arbol_avl.py ---

Árbol binario de búsqueda que se mantiene balanceado mediante rotaciones
simples (derecha/izquierda) y dobles (izquierda-derecha, derecha-izquierda).

Factor de balance = altura(izquierdo) - altura(derecho), debe ser -1, 0 o 1.

Uso en el sistema: El catálogo de productos se carga en un Árbol AVL usando
el nombre del producto como clave. Esto permite búsqueda O(log n), inserción
ordenada y visualización gráfica del árbol con los 3 recorridos.

Fragmento clave (inserción con balanceo):
  def _insertar_rec(self, nodo, clave, valor):
    if not nodo:
      return NodoAVL(clave, valor)
    if clave < nodo.clave:
      nodo.izquierdo = self._insertar_rec(nodo.izquierdo, clave, valor)
    elif clave > nodo.clave:
      nodo.derecho = self._insertar_rec(nodo.derecho, clave, valor)
    else:
      nodo.valor = valor
      return nodo
    self._actualizar_altura(nodo)
    balance = self._balance(nodo)
    # Rotaciones para auto-balanceo
    if balance > 1 and clave < nodo.izquierdo.clave:
      return self._rotacion_derecha(nodo)
    if balance < -1 and clave > nodo.derecho.clave:
      return self._rotacion_izquierda(nodo)
    if balance > 1 and clave > nodo.izquierdo.clave:
      nodo.izquierdo = self._rotacion_izquierda(nodo.izquierdo)
      return self._rotacion_derecha(nodo)
    if balance < -1 and clave < nodo.derecho.clave:
      nodo.derecho = self._rotacion_derecha(nodo.derecho)
      return self._rotacion_izquierda(nodo)
    return nodo


--- TAD Grafo (Matriz de Adyacencia) - structures/tad_grafo.py ---

Grafo no dirigido implementado con matriz de adyacencia.
Cada vértice es un producto, cada arista con peso representa la
cantidad de veces que dos productos se compraron juntos.

Uso en el sistema: El grafo de recomendaciones se construye analizando
pedidos históricos. Si el Café Americano y el Croissant aparecen juntos
en varios pedidos, se crea una arista entre ellos. BFS explora relaciones
nivel por nivel; DFS explora cadenas profundas de relaciones.

Fragmento clave:
  def agregar_vertice(self, vertice):
    if vertice not in self._indices:
      self._indices[vertice] = len(self._vertices)
      self._vertices.append(vertice)
      for fila in self._matriz:
        fila.append(0)
      self._matriz.append([0] * len(self._vertices))

  def agregar_arista(self, origen, destino, peso=1):
    i, j = self._indices[origen], self._indices[destino]
    self._matriz[i][j] = peso
    if not self.dirigido:
      self._matriz[j][i] = peso

  def bfs(self, inicio):
    visitados = set()
    cola = [inicio]
    recorrido = []
    while cola:
      vertice = cola.pop(0)
      if vertice not in visitados:
        visitados.add(vertice)
        recorrido.append(vertice)
        for ady in self.adyacentes(vertice):
          if ady not in visitados:
            cola.append(ady)
    return recorrido

  def dfs(self, inicio):
    visitados = set()
    pila = [inicio]
    recorrido = []
    while pila:
      vertice = pila.pop()
      if vertice not in visitados:
        visitados.add(vertice)
        recorrido.append(vertice)
        for ady in self.adyacentes(vertice):
          if ady not in visitados:
            pila.append(ady)
    return recorrido

6. ORQUESTACIÓN DE ESTRUCTURAS
========================================

El PedidoController (controller/pedido_controller.py) es el mejor ejemplo
de cómo conviven múltiples estructuras:

  class PedidoController:
    def __init__(self):
      self.dao = PedidoDAO()                    # Persistencia SQLite
      self.cola_pedidos = Cola()                 # Cola FIFO principal
      self.cola_espera = Cola()                  # Cola FIFO de espera
      self.pila_deshacer = Pila()                # Pila LIFO para deshacer
      self.lista_pendientes = ListaDoblementeEnlazada()  # Preparación

Flujo de un pedido:
1. Se crea → enqueue en cola_pedidos (FIFO)
2. Pasa a espera → dequeue de cola_pedidos, enqueue en cola_espera
3. Pasa a preparación → dequeue de cola_espera, insertar_final en lista_pendientes
4. Se marca listo → se actualiza estado
5. Se cobra → se crea venta en BD, se acumulan puntos

Cada paso se registra en la pila_deshacer para poder revertirlo.

11. SQL PARA DIAGRAMA DE BASE DE DATOS (DER)
========================================

El siguiente SQL puede copiarse en herramientas como dbdiagram.io,
drawSQL, MySQL Workbench, o cualquier generador de DER compatible
con SQLite/PostgreSQL para visualizar el diagrama entidad-relación:

```sql
-- ============================================
-- SACHAS CAFÉ - DIAGRAMA ENTIDAD-RELACIÓN
-- ============================================
-- Copiar y pegar en dbdiagram.io o similar

-- Tabla: producto
CREATE TABLE producto (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre TEXT NOT NULL UNIQUE,
    descripcion TEXT DEFAULT '',
    precio REAL NOT NULL,
    categoria TEXT NOT NULL,
    stock INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Tabla: cliente
CREATE TABLE cliente (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre TEXT NOT NULL,
    telefono TEXT DEFAULT '',
    email TEXT DEFAULT '',
    puntos INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Tabla: pedido
CREATE TABLE pedido (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    id_cliente INTEGER,  -- FK → cliente.id (opcional, puede ser NULL para 'General')
    fecha TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    estado TEXT DEFAULT 'en_cola',  -- en_cola | espera | preparacion | listo | completado | cancelado
    total REAL DEFAULT 0.0,
    FOREIGN KEY (id_cliente) REFERENCES cliente(id)
);

-- Tabla: detalle_pedido (relación muchos a muchos entre pedido y producto)
CREATE TABLE detalle_pedido (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    id_pedido INTEGER NOT NULL,   -- FK → pedido.id
    id_producto INTEGER NOT NULL, -- FK → producto.id
    cantidad INTEGER NOT NULL,
    subtotal REAL NOT NULL,
    FOREIGN KEY (id_pedido) REFERENCES pedido(id),
    FOREIGN KEY (id_producto) REFERENCES producto(id)
);

-- Tabla: venta
CREATE TABLE venta (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    id_pedido INTEGER UNIQUE NOT NULL, -- FK → pedido.id (1 pedido → 1 venta)
    total REAL NOT NULL,
    metodo_pago TEXT DEFAULT 'efectivo',  -- efectivo | tarjeta | yape | plin
    fecha TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (id_pedido) REFERENCES pedido(id)
);
```

Relaciones del diagrama:
  ┌──────────┐       ┌──────────────┐       ┌────────────────┐
  │ cliente  │1──N──>│   pedido     │1──N──>│ detalle_pedido │
  └──────────┘       └──────────────┘       └───────┬────────┘
                           │ 1                      N │
                           │                         │
                           v                         v
                     ┌──────────┐              ┌──────────┐
                     │  venta   │              │ producto │
                     └──────────┘              └──────────┘

  NOTA: pedido → venta es 1:1 (un pedido genera una sola venta al cobrar)
        pedido → detalle_pedido es 1:N (un pedido tiene múltiples detalles)
        producto → detalle_pedido es 1:N (un producto aparece en varios detalles)
        cliente → pedido es 1:N (un cliente puede tener muchos pedidos)
